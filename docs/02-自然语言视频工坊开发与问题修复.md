# 自然语言视频工坊：开发过程与修过的问题

外围「框」指 `video-studio/`：用户用中文说话、选选项、过评审，由服务端把镜头交给 Hailuo 或本机 H3。本文按时间线写给后来接盘的人，避免重复踩坑。

## 1. 框架：外围框解决什么

用户明确需求是：**不要看懂 ComfyUI 工作流**，要像 MiniMax Design 那样对话推进，直到出视频。

因此工坊分成三层，H3 只出现在最后一层：

```
聊天 / 选项 / 画布（React，4175）
        │
编排与门禁（Express：阶段、项目、M3、Hailuo、Comfy 客户端）
        │
本机 H3 或云端 Hailuo
```

云端 M3 当导演脑；每天约 3 次 Hailuo 额度当「成片镜」；本地 H3 当草稿工人。阿里云 **只做反向 SSH 转发**，导演台不搬家。

## 2. 设计演进（做外围框时怎么改目标）

### 阶段 A：按钮控制台

输入框 +「生成分镜」+ 每个镜头「生成」+ 手动合并。后台已经能调 M3、Hailuo、Comfy `/prompt`。问题：用户仍要当导演，每一步自己点。

### 阶段 B：对话触发执行

聊天里说「开始」就排队。踩过坑：用正则匹配「开始拍」等词，用户说「开始」被丢掉，导演口头答应了但 Comfy 没任务。

### 阶段 C：阶段门禁（当前主干）

对齐 MiniMax Design 的「见解 + 选项 + 画布评审」：

```
discovery → brief_review → concept_selection → storyboard_review
  → quality_review → ready_to_generate → generating → delivery_review → delivered
```

硬规则（`AGENTS.md`）：

- **阶段由服务端拥有**，模型只能建议 `actions`，不能跳过门。
- **聊天禁止直接开拍或合并。** 开拍是独立按钮 + 独立 API。
- 简报确认、选创意方向、确认分镜、质量通过、开拍、交付，各走各的 POST。
- 返修要作废下游批准，但不要删源素材。
- 上传的图必须当多模态 `image_url` 真正发给 M3，不能假装模型看见了文件名。

这才是「本地 Agent 产品」该有的形状：LLM 负责理解与提案，工具与门禁负责安全执行。

## 3. 开发步骤（新人按这个拆任务）

1. **项目落盘**  
   `outputs/projects/<id>/project.json` + `images/`。刷新不能丢聊天、分镜、任务 id。

2. **导演契约**  
   M3 只输出 JSON：`say`、`insight`、`choices[]`（2–4 个有差异的选项，含完整 `reply`）、`actions`。解析在 `director.mjs`，编排在 `server.mjs`。

3. **阶段 API**  
   例如 `confirm-brief`、`select-concept`、`confirm-storyboard`、`approve-quality`、开拍、交付。旧的 `/api/local/generate` 等直达接口已 **410 停用**。

4. **把镜头映射到 H3**  
   提示词、画幅、时长、该镜自己的参考图 → `buildH3Prompt` → `/prompt` → 轮询 `/history` → 复制到 `outputs/local/`。

5. **Hailuo 旁路**  
   明确确认次数后再提交；不要在日常测试里真烧额度。

6. **合片**  
   多镜成功后 FFmpeg concat。编码不一致时以后再重编码。

7. **远程**  
   本机 `ssh -R 127.0.0.1:17415:127.0.0.1:4175`，阿里云 nginx `:8110` 反代。PWA 在 `video-studio/public/`。

8. **无 GPU 测试**  
   `STUDIO_VIDEO_DEMO_MODE=1` 只模拟出片；`STUDIO_DIRECTOR_DEMO_MODE=1` 才用假导演。正式环境两个都是 `0`。

验收命令：

```powershell
cd video-studio
npm.cmd run build
npm.cmd run lint
npm.cmd test
Invoke-RestMethod http://127.0.0.1:4175/api/status
```

## 4. 修过的问题（按主题）

### 4.1 交互：按钮台 ≠ Design

- **现象：** 能出分镜和排队，但必须自己选引擎、点每个镜头。
- **处理：** 聊天 + 右侧分镜/预览；后来改成阶段画布，开拍从聊天里拿掉。
- **教训：** 「能调通 API」只完成了 40%。Agent 产品要自己推进下一步，同时用门禁防止误开拍。

### 4.2 「开始」没有真正开渲

- **现象：** 导演说「本地草稿开始生成」，镜头仍是 `ready`，Comfy 队列为空。
- **原因：** 服务端用正则过滤 `generate`，只认「开始拍」「开始生成」，用户说「开始」被丢掉。
- **处理：** 一度改为完全信任模型 JSON；当前主干则是 **聊天根本不允许 generate**，开拍走按钮。不要再加一套关键词开拍。

### 4.3 导演 JSON 解析失败

日志类似：

```text
[director] structured reply invalid; retrying with compact context
  finishReason: 'stop', contentLength: 431, reason: '导演未返回有效 JSON'
```

- **含义：** M3 正常结束，但正文不是 `{say, insight, choices≥2, actions}`。不是 Comfy 崩了。
- **处理：** `jsonrepair`、去掉 `<think>`、分段 `content` 拼接、失败则缩短上下文重试。
- **教训：** 对中文模型必须假定「偶尔不守 JSON」。重试和修复是功能，不是权宜之计。

### 4.4 CLIP 类型 `wan`

手测工作流里 CLIPLoaderGGUF 曾写成 `wan`。能出 mp4，人和口令对不齐。工坊组图已固定 `type: 'minimax'`。

### 4.5 一张图绑所有镜头

早期 `firstFrame` 全局共用，玄奘 S1–S4 四张图无法分别绑定。现在参考图是项目资产，按镜头绑定，聊天里以多模态发给 M3。

### 4.6 项目刷新丢失

任务列表有，分镜和 taskId 对不上。必须把 `project.json` 当唯一项目真源，任务表只是执行日志。

### 4.7 启动与转发

- 4175 已占用时不要再起第二个 Node。
- 服务没 listen 完就打开浏览器会连不上：先等端口再 `start http://127.0.0.1:4175`。
- 阿里云 80/443 未备案会拦截；公网用 `http://47.108.114.17:8110`。
- 反向 SSH 的 Host 要以 `.ssh/config` 里实际名字为准（仓库里脚本使用 `aliyun_ecs`）。
- 本会话里长时间后台进程会被超时杀掉（Comfy / Node / SSH），部署时要用本机开机启动，不要依赖某个聊天会话里的后台任务。

### 4.8 HTTP 上的选项按钮

PWA 当前是 HTTP。部分浏览器对 choice 的提交和 Service Worker 不友好，后续有专门修复「不安全源上的选项」。测手机时看控制台，不要只看桌面。

### 4.9 演示模式把导演状态搞混

旧开关会让页面显示「导演已连接」其实是假数据。现在拆开：`STUDIO_VIDEO_DEMO_MODE` 只假出片，`STUDIO_DIRECTOR_DEMO_MODE` 才假导演。

## 5. 完成标准（外围框）

- [ ] 无 GPU 也能走完访谈 → 简报 → 方向 → 分镜（演示或真实 M3）。
- [ ] 有 GPU 时，确认分镜后点开拍，镜头出现 `Queueing/Processing`，完成回填预览。
- [ ] 用户不用打开 8188。
- [ ] 密钥只在根目录 `.env`，不进 Git、不进前端、不进日志。
- [ ] `npm test` 覆盖阶段门禁和 `insight + choices` 契约，不依赖 GPU、不提交 Hailuo。

未完成（不要假装做完）：旁白/字幕后期、Ref2VA 身份锁、无缝长镜头链、可信 HTTPS 的 PWA 安装。
