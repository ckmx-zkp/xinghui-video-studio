# 第一集《玄奘入戏》测试方案

## 目的

先用 S1–S4 做第一轮 image-to-video 测试，验证人物一致性、动作遵循、镜头稳定性和声音/字幕后期流程；再扩展到 S5–S8。

## 参考图映射

按用户本轮上传的 4 张图排列：

| 镜头 | 参考图 | 建议用途 |
|---|---|---|
| S1 译经终点 | 图 1：老年玄奘持经卷 | image-to-video 起始帧，合卷、闭目 |
| S2 无形大手扭转因缘 | 图 3：经文与时空裂隙 | image-to-video 起始帧，文字旋转、漩涡拉远 |
| S3 一眼读完西游梗概 | 图 4：西游书页蒙太奇 | image-to-video 起始帧，书页翻动、信息洪流 |
| S4 年轻唐僧现身 | 图 2：年轻唐僧与老年玄奘虚影 | image-to-video 起始帧，低头看手、虚影稳定显现 |

不要把四张图合并成一张参考图；每个镜头应有自己的参考图和自己的提示词。

## 第一轮建议时长

当前本地/云端工坊按 6 秒单镜头设计，因此先统一生成：

- S1：6 秒
- S2：6 秒
- S3：6 秒
- S4：6 秒
- 第一轮成片：24 秒，片头片尾字幕另加 3–4 秒

这 24 秒只作为技术测试，不代表完整第一集的最终节奏。S1 和 S4 动作较慢，6 秒够用；S2、S3 信息量较大，后期可从 6 秒素材中截取精华，或拆为 2 个 6 秒镜头。

## 完整第一集建议时长

建议成片控制在 55–70 秒：

| 部分 | 建议时长 |
|---|---:|
| 片头字幕 | 2–3 秒 |
| S1 | 5–6 秒 |
| S2 | 6–8 秒 |
| S3 | 6–8 秒 |
| S4 | 6 秒 |
| S5 观音献宝 | 7–9 秒 |
| S6 拒绝被安排 | 10–12 秒，建议拆成两个镜头 |
| S7 观音显真身 | 7–9 秒 |
| S8 五行山钩子 | 5–7 秒 |
| 结尾字幕 | 2 秒 |

台词较多时，不要强行让视频模型生成口型对白；建议视频模型只负责动作和镜头，旁白、对白、音效、字幕在剪辑阶段完成。这样更容易控制节奏，也避免中文口型和文字生成错误。

## 时间估算（9070 XT 16GB + 48GB RAM，本地 H3）

这是保守规划值，不是机器实测承诺：

- 首次加载模型和工作流：10–30 分钟（取决于磁盘和缓存）。
- 低/中分辨率 6 秒草稿：每镜头约 10–25 分钟。
- S1–S4 各出 1 条：约 1–2 小时；加上挑选、重跑和剪辑，预留半天。
- 完整 S1–S8 各出 1 条：约 3–6 小时；每镜头重跑 1–2 次时，预留 1–2 天。
- 720P、复杂时空特效或高步数会显著变慢，应先做 512/576P 草稿，再对选中的镜头升到 720P。

公开的 16GB NVIDIA 测试中，约 10 秒低分辨率片段可在数分钟内完成，但同卡全分辨率测试可超过 15 分钟；AMD/Windows/ROCm 与该测试环境不同，因此以上时间只作为接手 agent 的排期依据，第一次跑通后应记录本机实际秒数再修正。参考：[16GB H3 实测记录](https://github.com/Tomiigo/minimax-h3-16gb)。
